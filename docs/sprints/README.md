# Sprints — the plan of all work

The contract is Keel's `references/project-state.md`: "Sprint files (Phase 5) — template" and "The sprint plan — one plan, three layers, one job each". This file only says where things are.

## Three layers, one author each

1. **Authority, edited by hand:** `sprint-<N>.md`. The frontmatter (`schema: keel.sprint/1`) is where a slice's status, hours and dependencies live, and the only place they are edited. The body is prose for people.
2. **Backlog, edited by hand:** [`deferred.md`](deferred.md) (`schema: keel.deferred/1`). Everything wanted and not in the current plan, with `target:` and `reason:`. Its ids share one namespace with the sprint slices, so promoting an item moves it and keeps its id.
3. **Derived, never edited by hand:** `docs/.keel/plan.json` and the index table below, both written by `scripts/keel-plan build`. Totals and percentages are computed there from hours and are stored nowhere else.

## Working with it

- Every piece of work is a slice, added with its hours before its first change.
- `scripts/keel-time slice-end <id> --status done` writes the slice's measured `actual_hours`; a status or hours change made by hand is followed by `scripts/keel-plan build`.
- `scripts/keel-plan check` fails when `plan.json` or the table below has drifted from the sprint files.
- `scripts/keel-plan left` answers "what is left?".
- Sprint 1 is a backfill of the work done before this plan existed; its hours are estimates, not measurements.
